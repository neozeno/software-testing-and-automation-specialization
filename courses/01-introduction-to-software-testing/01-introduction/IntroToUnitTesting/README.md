# Building Unit Tests with JUnit

In this assignment, I got some practice at building effective unit tests.
Using the example from the videos, I developed tests for the `Demo` class,
including the `isTriangle()` and `main()` methods.

My task was to create a file, `DemoTest.java`, which properly tests the `Demo`
class to ensure it is working properly. The correct `Demo.java`
file was provided for my use.

Below, are the assignment instructions.

## Deliverable

My deliverable was the `DemoTest.java` which tests the `Demo` class.

## Evaluation

In order to measure the adequacy of my tests, they used mutation analysis,
by generating many variations of the `Demo.java` file, each with a single fault
introduced. These faults (mutations) included things like swapping a binary
operator for another (e.g., '+' instead of '-'), or changing the variable used
for another variable of the same type (e.g., 'a' substituted for 'b').

### Package Prerequisites

- Java 8 JDK
- An IDE of your choice

## Building

This contains instructions for building the project. The unmodified, original
set of files in this project will build correctly.

### From Eclipse

1. To build the project, use the "Gradle Tasks" view. If you don't have it, go to
  | `Window > Show View > Other` and from the Gradle folder, double click
  | on "Gradle Tasks".

2. In the "Gradle Tasks" view, expand the project folder. Then, expand "build".
  | Double-click on "build". You will be taken to the "Gradle Executions" view,
  | where you will see the results of running each step in the gradle build
  | script. The project should build successfully (at least before you make
  | any changes). To view what was printed to the screen by the build, open the
  | "Console" view.

3. If you need to clean the project (delete all compiled files), double-click
  | on the "clean" target in the "Gradle Tasks" view in build under the
  | project folder.

### From Command-Line

To compile from command-line:
1. Execute `./gradlew build` (on UNIX; including macOS) or `gradlew.bat build`.
  | This will download gradle and all required libs (on the first run only).
  | Then, it will compile the code, execute the Cucumber tests. The test results
  | are emitted as a report to `build/reports/tests/test/index.html`. 

2. To open a report in a browser, append "file://" before the full path
to the file (on Windows, change the "/" to "\\"), or navigate to the directory
and open the file with the browser.
For example, `file:///\<pathToExpandedProject\>/build/reports/tests/test/index.html`,
opens the JUnit test report on my system once you replace
`pathToExpandedProject` with the actual path.

3. If you need to clean the project (delete all compiled files), execute
`./gradlew clean` (Linux/UNIX/MacOS) or `gradlew.bat build` (Windows).

### From Other IDEs

You can run this project within any Gradle-capable IDE (e.g., InteliJ IDEA,
NetBeans with the Gradle plugin). Consult your IDE's instructions for how
to set this up.

## Directory Structure

 * `build.gradle`: the build file that will help you build the SUT and tests
  | as well as execute the tests and measure coverage
 * `gradlew`: script to run gradle from a Linux/UNIX system (including MacOS).
 * `gradlew.bat`: script to run gradle from Windows
 * `src/main/java`: contains the system under test (SUT; in this case,
  | `Demo.java`). Do not modify this code.
 * `src/test/java`: the JUnit test code that you develop. We provided an empty
  | `DemoTest.java` file to get you started.
 * `build/reports`: contains the different reports generated by the build. NOTE:
  | This directory will only exist once a gradle build has been run!
   - `tests/test/index.html`: the JUnit test report (describing which tests
    | passed and which failed); this file is only created if the unit
    | tests are executed.
